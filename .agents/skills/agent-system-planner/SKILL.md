# Agent System Planner Skill

You are the evolution engine for the LMS Co-Pilot agent system.
Your job is to detect patterns in session history that indicate the need for
NEW skills, rules, MCP servers, or hooks — and plan them for approval.

## When to Activate

Run this skill when:
- The user says "what skills are we missing?" or "plan new skills"
- A task was handled ad-hoc more than once and could be automated
- The agent couldn't access data it needed (potential MCP need)
- Something should have triggered automatically but didn't (potential Hook need)

## Step 1: Pattern Detection

Scan the current session history for these patterns:

| Pattern | Threshold | Component to Propose |
|:--------|:----------|:--------------------|
| Same task explained to agent | ≥ 2 times | New **Skill** |
| Same coding constraint enforced manually | ≥ 2 times | New **Rule** |
| Agent needed external data it couldn't read | ≥ 1 time | New **MCP Server** |
| Task should auto-fire on an event | ≥ 1 time | New **Hook** |
| Same slash command + same args | ≥ 3 times | New **Workflow** |

## Step 2: Inventory Existing Components

Before proposing, check what already exists:

**Existing Skills:** (list current .agents/skills/ folders)
- `rag-debug-analyst`
- `search-pipeline-linter`
- `commit-message-generator`
- `service-bootstrapper`
- `arabic-content-qa`
- `agent-system-updater`
- `agent-system-planner`

**Existing Rules:**
- `python-typing.md`
- `async-safety.md`
- `service-pattern.md`

**Existing MCPs:** (from `.agents/mcp_config.json`)
- `filesystem` — access to `downloads/search_debugs/`
- `fetch` — HTTP fetch for API health checks

**Existing Hooks:** (from `.agents/hooks.json`)
- `pre-commit-pipeline-check` — triggers linter before git commit

Only propose NEW components not already covered.

## Step 3: Write the Proposal File

Write to: `.agents/proposals/new_components_YYYYMMDD_HHMMSS.md`

Use this exact format:

```markdown
# New Agent Components Proposal — [DATE]
Generated by: /agent-system-planner
Session patterns analyzed: [N] patterns found

---

## Proposal 1: New Skill — `[skill-name]`

**Pattern Observed:**
[Describe the repeated task or gap]

**Current State:**
[What happens now — ad-hoc, manual, incomplete]

**Proposed SKILL.md:**
```yaml
---
name: [skill-name]
description: >
  [50-word description with activation keywords]
---
```

**Proposed Core Instructions:**
[Outline the key steps the skill should encode]

**Estimated Value:** [High/Medium/Low] — [one sentence why]

---

## Proposal 2: New Rule — `[rule-name].md`

**Pattern Observed:** [Repeated constraint the agent forgot]
**Proposed Rule Content:** [Draft the rule text]

---

## Proposal 3: New MCP Server — `[server-name]`

**Gap Identified:** [What data the agent couldn't access]
**Proposed Config:**
```json
{
  "[server-name]": {
    "command": "...",
    "args": [...]
  }
}
```

---

## Proposal 4: New Hook — `[hook-name]`

**Gap Identified:** [What should auto-trigger but doesn't]
**Proposed Hook Config:**
```json
{
  "name": "[hook-name]",
  "trigger": "...",
  "condition": "...",
  "skill": "..."
}
```

---

## Approval Instructions

For each numbered proposal, reply:
- "approve 1" — implement proposal 1
- "approve all" — implement everything
- "reject 2" — discard proposal 2
- "modify 3: [your changes]" — revise proposal 3 before implementing

I will NOT implement anything until you approve.
```

## Step 4: STOP and Wait

After writing the proposal:
1. Summarize the proposals in your response (don't repeat the full file)
2. Tell the user to review `.agents/proposals/new_components_[DATE].md`
3. Wait for approval before creating ANY new files

## After Approval

When the user approves a specific proposal:
1. For new Skills: create the full `.agents/skills/[name]/SKILL.md`
2. For new Rules: create `.agents/rules/[name].md`
3. For new MCPs: update `.agents/mcp_config.json`
4. For new Hooks: update `.agents/hooks.json`
5. Then run the `agent-system-updater` to register the new component in the inventory
