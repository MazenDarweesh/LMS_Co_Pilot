# 📡 وثيقة متطلبات وتكامل شريط الفلاتر الذكي لشاشة المحادثة
## (LMS AI Co-Pilot Top Filter Bar Specification)
- **موجهة إلى:** فريق تطوير المنصة الأساسية (`DynamicProLearn` — .NET 10 Web API & Angular 19 UI)
- **صادرة من:** محرك الذكاء الاصطناعي (`LMS_CO_Pilot` — Python / FastAPI / Qdrant)
- **الحالة:** معتمدة وموجهة للتنفيذ (Canonical Feature Specification)

---

## 🎯 1. الهدف العام للميزة (General Feature Objective)

تمكين الطالب في شاشة محادثة **LMS AI Co-Pilot** من توجيه أسئلته وتحديد نطاق البحث بدقة عبر **شريط فلاتر علوي (Top Filter Bar)** في أعلى نافذة الشات، بحيث يستطيع:
1. السؤال بشكل **عام** على مستوى كل المحتوى المصرح له برؤيته.
2. أو تضييق السؤال على **موديول معين (Module)**.
3. أو تضييق السؤال على **وحدة معينة (Unit)**.
4. أو تضييق السؤال على **درس محدد (Lesson)**.
5. الفلترة الإضافية حسب **المستوى التعليمي (Level)** (مثل: مبتدئ، متوسط، متقدم) وحسب **نوع المحتوى (Type)** (مثل: فيديو، مستند PDF، عملي).

> [!IMPORTANT]
> **قيد الأمان الصارم (RBAC Requirement):**
> لا يجوز للواجهة أن تعرض للطالب في القوائم إلا الموديولات والوحدات والدروس التي يملك الطالب صلاحية أو تسجيلاً نشطاً (`Active Enrollment`) فيها فقط.

---

## 🏢 2. الأهداف المطلوبة من جانب الـ Backend (.NET 10 Web API)

> **ملاحظة للفريق:** نترك لكم حرية تقييم هيكلية الـ Controllers والخدمات لديكم واختيار أفضل طريقة لتنفيذ هذه النقاط وفق معايير Clean Architecture المعتمدة في مشروعكم.

### 2.1 توفير نقطة نهاية لإرجاع شجرة المحتوى المصرح بها للطالب
- **الهدف:** تزويد واجهة Angular بقائمة الكيانات المسموحة للطالب فقط ليتم عرضها في القوائم المنسدلة لشريط الفلاتر.
- **المسار المقترح:** `GET /api/v1/student/copilot-filters` (أو مسار مماثل من اختياركم محمي بـ `[Authorize]`).
- **البيانات المتوقعة في الرد:**
  - مصفوفة الموديولات المصرح بها للطالب الحالي فقط:
    - `id`, `title`, `code`
    - قائمة الوحدات التابعة للموديول: `id`, `title`
    - قائمة الدروس التابعة لكل وحدة: `id`, `title`, `levelId`, `typeId`
  - قوائم المستويات والأنواع المتاحة للمساعدة في بناء الـ Chips/Dropdowns في الواجهة:
    - `levels`: مثل `[{ "id": "beginner", "name": "مبتدئ" }, ...]`
    - `types`: مثل `[{ "id": "video", "name": "فيديو" }, { "id": "pdf", "name": "مستند PDF" }, ...]`

## 🌐 3. الأهداف المطلوبة من جانب الـ Frontend (Angular 19 UI)

> **ملاحظة للفريق:** نترك لكم حرية تقييم المكوّنات، وتوزيع ملفات الـ Components، واختيار إدارة الحالة (Signals أو RxJS) الأنسب لتصميمكم الحالي.

### 3.1 بناء مكوّن شريط الفلاتر العلوي (Top Filter Bar Component)
- يوضع أعلى نافذة الشات (`copilot-chat`), أسفل شريط العنوان وأعلى منطقة استعراض الرسائل.
- **عناصر التحكم المطلوبة:**
  1. **محدد النطاق الرئيسي (Scope Selector):**
     - `[ 🌐 الكل | 📚 موديول | 📑 وحدة | 🎯 درس محدد ]`
  2. **القوائم المتتالية (Cascading Selects):**
     - تظهر القوائم المنسدلة وفق النطاق المختار (مثال: اختيار "درس" يتيح اختيار الموديول ثم الوحدة ثم الدرس).
     - القوائم لا تعرض إلا ما استرجعه الـ API للطالب.
  3. **فلاتر المستوى والنوع (Level & Type Filters):**
     - قوائم أو أزرار شرائح (Chips/Pills) للاختيار الاختياري:
       - المستوى: [الكل | مبتدئ | متوسط | متقدم]
       - النوع: [الكل | فيديو 🎬 | مستند PDF 📄 | عملي ⚙️]
  4. **زر إعادة ضبط الفلاتر (Reset Button):**
     - زر بنقرة واحدة يعيد النطاق فوراً إلى `الكل (All)` ويمسح كافة التحديدات.
  5. **شارات النطاق النشط (Active Scope Badge):**
     - مؤشر بصري مدمج يوضح للطالب سياق بحثه الحالي (مثال: `🔍 النطاق: موديول المحاسبة > قيود اليومية [مبتدئ]`).

### 3.2 الالتقاط السياقي التلقائي (Context Auto-Detection)
- إذا فتح الطالب المساعد الذكي وهو يتصفح بالفعل صفحة درس معين (مثال: `/courses/:id/lessons/:lessonId`)، يُفضل أن يكتشف الشات تلقائياً هذا الدرس ويضبط الفلتر عليه افتراضياً، مع إبقاء خيار التوسيع إلى `الكل` متاحاً دائماً بنقرة واحدة.

### 3.3 إرسال الفلاتر المختارة مع طلب البحث
- عند إرسال الطالب لأي سؤال عبر مسار البث المباشر `POST /v1/search/stream` (أو `POST /api/search/stream`)، يتم تضمين الفلاتر في جسم الطلب (Request Body) وفق العقد الموضح أدناه.

## 📋 4. عقد طلب البحث المعتمد مع محرك الذكاء الاصطناعي (AI Request Contract)

- **الـ Endpoint:** `POST /v1/search/stream` (أو `POST /api/search/stream`)
- **Headers:**
  - `Content-Type: application/json`
  - `Authorization: Bearer <Student_JWT_Token>`
- **صيغة الـ JSON Body:**
```json
{
  "query": "سؤال الطالب هنا...",
  "scope": "lesson",
  "moduleId": "mod-101",
  "unitId": "unit-01",
  "lessonId": "les-05",
  "levelId": "beginner",
  "typeId": "video",
  "threadId": "3fa85f64-5717-4562-b3fc-2c963f66afa6",
  "limit": 5,
  "skipCache": false
}
```

### 💡 جدول تفصيل الحقول ودلالتها في المحرك:
| الحقل في الطلب | النوع | اختياري/إجباري | القيم المدعومة والأوصاف |
|---|---|---|---|
| `query` | string | **إجباري** | نص سؤال الطالب (يدعم أيضاً `message`, `question`). |
| `scope` | string | اختياري (افتراضي `"all"`) | النطاق: `"all"`, `"module"`, `"unit"`, `"lesson"`, `"course"`, `"standalone"`, `"playlist"`. |
| `moduleId` | string | اختياري | معرّف الموديول (يقبل أيضاً `module_id` أو `ModuleId`). |
| `unitId` | string | اختياري | معرّف الوحدة (يقبل أيضاً `unit_id` أو `UnitId`). |
| `lessonId` | string | اختياري | معرّف الدرس (يقبل أيضاً `lesson_id` أو `LessonId`). |
| `levelId` | string | اختياري | معرّف المستوى التعليمي (يقبل أيضاً `level_id` أو `LevelId`). |
| `typeId` | string | اختياري | معرّف نوع المحتوى (يقبل أيضاً `type_id` أو `TypeId`). |
| `threadId` | string | اختياري | معرّف جلسة المحادثة لحفظ سياق الحديث. |
| `skipCache`| boolean| اختياري (افتراضي `false`) | يرسل `true` عند ضغط الطالب على "إعادة التوليد" (Regenerate). |

---

## 🔒 5. ملاحظة هامة حول الأمان في محرك الذكاء الاصطناعي
- محرك الذكاء الاصطناعي مهيأ بطبقة حماية **Fail-Closed Zero Trust**.
- يقوم المحرك بربط أي فلتر قادم في الطلب بتقاطع حتمي (`must AND`) مع صلاحيات الطالب المستخرجة من الـ JWT والـ ERP (`user_entities`).
- في حال إرسال أي معرّف غير مصرح به من العميل، يرفض محرك البحث في Qdrant الطلب تلقائياً وتكون النتيجة **0 نتائج** فوراً دون تسريب أي بيانات.
